# rxlib 量化研究平台

<p align="center">
  <img src="logo.png" alt="rxlib 标志" width="200" />
</p>

本地运行的 A 股量化研究 / 因子回测平台。提供图形化界面，基于 **Lance Breitstein
「五要点」** 交易方法，用纯 **OHLCV K 线**完成活跃度 → 干净价位 → 盘整/情绪 →
多周期共振的五层量化筛选与回测。
行情数据可通过 **API**、**直连 MySQL** 或 **本地 CSV 导入**三种方式获取，默认以收盘口径为准。

- 当前版本：**1.0.1**
- 运行时：便携 Python **3.12**（随包附带，无需自行安装）
- 默认端口 **8504**

> ⚠️ **风险提示：市场有风险，投资需谨慎。**
>
> 本平台为**量化选股 / 因子回测研究工具**，框架与指标源自美股交易者 Lance Breitstein
> 的支撑与阻力方法论，**仅用于个人学习、研究与历史回测，不构成任何投资建议，
> 亦不推荐用于实盘交易**。历史回测不代表未来收益，过往表现不预示未来结果。
> 请特别注意：美股与 A 股在交易机制上存在显著差异（如 T+1 / T+0、涨跌停限制、
> ST 制度、交易时段、印花税与滑点成本等），系统已在回测中加入涨跌停、ST、
> 最小上市天数等 A 股约束，但仍无法完全还原实盘摩擦与真实成交。**据此操作，风险自担。**

### 五要点的应用场景

Lance Breitstein「支撑与阻力五要点」本质是一套**量价行为 / 支撑阻力识别**的合力框架，
在如下行情场景中最有参考价值：

- **缩量盘整后的放量突破**：区间被持续压缩、量能干净、ROC 加速越过年均成本（AVWAP）——
  适合管道 A（盘整突破）捕捉强势启动；
- **恐慌投降后的情绪反转**：带量加速下探出现投降 K 线、随后收复锚定 AVWAP——
  适合管道 B（情绪反转）捕捉超跌反弹；
- **多周期同向共振**：日 / 周 / 月方向一致的标的共振评分高、对应更高仓位；
- **活跃标的池初筛**：从全市场快速收敛到"正在放量、被资金撬动"的少数强势股。

不适合的场景包括：量能杂乱无章的宽幅震荡、趋势方向未定、日 / 周 / 月分歧显著、
上市时间不足、处于涨跌停无法成交等，这类标的多会被五要点条件过滤。

### 该方法选择标的最大特色

**以"成交量 / 活跃度"为核心驱动，专注处于资金焦点的高波动标的。**

- **只选"正在被撬动"的个股**：入场前强制要求成交量放大（相对均量多倍）、波动与 ATR
  放大，专做机构与游资注意力集中的活跃股，而非抄底无人问津的冷门股；
- **围绕支撑 / 阻力位做择时**：要么"放量突破阻力位买入"（管道 A），要么"放量守住支撑、
  收复 AVWAP 买入"（管道 B）；
- **注意：选中的标的往往已处于相对高位**。由于成交量放大常在上涨途中出现，
  筛选结果天然偏向"已走出一定涨幅、处于价格高位的强势股"，抢筹成本偏高；
  而追高的同时，也需承担"冲高回落 / 缩量后回撤"的短期风险。平台内置移动止盈、
  趋势破坏等出场保护用于应对回撤，但仍然不是稳赚策略。提示：该方法可供研究的方向主要是入场信号。

> ⚠️ **量化边界的说明：该方法无法被一组公式完全还原。**
>
> Lance Breitstein「支撑阻力五要点」本质是交易者基于图表的**经验型量价研判**——
> 对支撑 / 阻力有效性、盘整蓄势的"健康程度"、情绪"投降"的阴谋程度等，存在大量
> 需要人眼主观判断与综合权衡的成分，**并不能用精确公式 1:1 完全量化**。
> 本平台只能抽取其中"可用纯 OHLCV 客观计算"的维度（活跃度、价位置信度、区间压缩、
> 布林 / 量能情绪、多周期共振等）做量化近似与结构化实现，并加上必要的平台适配
> （A 股约束、出场保护）。因此**计算结果是对原方法的有损量化投影，忠实度存在边界，
> 与原作者本人的人工交易判断可能有明显差异**，请在使用时知悉。

## 策略方法论与适合性

本平台的全部信号均来自 **Lance Breitstein「五要点」**，全部按纯 OHLCV 可计算，组织为五层，
再加一个「综合双管道」筛选框架：

**五要点（Activity 活跃度 → Clean Level 干净价位 → Consolidation 适当盘整 →
Emotion 情绪反应 → Resonance 多周期一致）**：

1. **活跃度（Activity）**：ATR 倍数、量能倍数、跳空 + 横截面活跃度评分，只筛选活跃标的；
2. **干净价位（Clean Level）**：枢轴位识别 / 价位置信度 / 突破速度 / 锚定 VWAP，
   只在清晰价区位进场；
3. **适当盘整（Consolidation）**：区间压缩 / 净漂移 / 回归斜率 / 均匀度 / 量价结构，
   要求健康蓄势而非杂乱宽幅；
4. **情绪反应（Emotion）**：布林带偏离 / 量能情绪 / 加速度 / 连续同向 K 线 + 投降 K
   线与收复 AVWAP 的入场确认；
5. **多周期一致（Resonance）**：日→周→月趋势合成 / 共振评分 / 仓位缩放 / 关键位重合。

**综合双管道筛选（`breitstein_screen`）**：管道 A（盘整突破 breakout）与管道 B
（情绪反转 reversal）共用活跃度 + 干净价位前置、互不拦截，任一命中即产生机会。
界面上「入场管线」可在 **A 盘整突破 / B 情绪反转 / A+B 双管道并行（默认）** 三档间切换，
单档模式只启用对应管道。

**出场优先级链（`_EXIT_RANK`）**：固定止损 > 结构/AVWAP > ATR > 共振走弱 > 活跃衰减 > 到期。

Breitstein 五要点以量价行为客观可复用为核心，但有明确的适合行情：

- **缩量盘整后的放量突破**：区间被持续压缩、量能干净、ROC 加速越过年均成本（AVWAP），
  适合管道 A（盘整突破）捕捉；
- **恐慌投降后的情绪反转**：带量加速下探出现投降 K 线、随后收复锚定 AVWAP，
  适合管道 B（情绪反转）捕捉；
- **多周期同向**：日/周/月方向一致的标的共振评分高，对应更高仓位。

五要点并非万能，以下情况成功率低：量能杂乱无章的宽幅震荡、趋势方向未定、
日/周/月分歧显著（共振评分为负）、个股上市不足、处于涨跌停无法成交。

> 使用原则：先看活跃度与干净价位，再进入盘整 / 情绪判定，最终以多周期共振决定进与仓位；
> 阈值需结合本地行情回测校准。以上仅为交易学习与历史回测方法，**不构成投资建议**。

## 一、快速开始

### 1. 启动

双击项目根目录下的：

```
start.bat
或者
启动量化平台.bat
```

它会调用 `run.ps1`，自动完成：

1. 读取 `app/current/manifest.json`，确定本版本所需的便携 Python（python312）；
2. **首次运行**：若本地缺少运行环境，自动从 `manifest.json` 指定的地址下载便携
   Python（约数百 MB，仅首次）并校验、解压，之后本地复用；
3. 以隔离依赖方式启动服务；
4. 等待服务就绪后自动打开浏览器，访问 `http://localhost:8504`。

> 端口被占用时，脚本会直接打开已在运行的页面。如需自定义端口，
> 可在 PowerShell 中执行：`.\run.ps1 -Port 8599`。

> 提示：`runtime\`（便携 Python + 依赖，约 500MB）不随代码库一起分发。
> 你拿到的是纯代码包，首次启动时按上面的步骤自动补齐运行环境；
> 或手动把运行时包解压到 `runtime/python312` 亦可跳过下载。

### 2. 登录

首次打开需输入访问密码(默认：rxlib)。密码以哈希形式保存在本地设置文件中，
可在登录后于「系统设置」中修改。

### 3. 基本使用流程

```
登录 → 左侧侧边栏选择数据源与参数 → 进入对应功能标签页 → 点击「运行」
```

## 三、数据源配置

在左侧「数据源」中选择数据提供层：

| 模式           | 说明                            | 是否需要本地数据库 |
| ------------ | ----------------------------- | ---------- |
| **API（默认）**  | 经 HTTP 接口取数，不连接本地 MySQL         | 否          |
| **直连 MySQL** | 直接读取本地行情库                     | 是          |
| **本地 CSV 导入** | 读取 `config/config.ini` 中 `[import]` 指定的目录下的月度 CSV | 否          |

配置文件位于 `config/config.ini`（首次缺失时会自动生成模板），主要字段：

```ini
[db]
host = 127.0.0.1
port = 3306
database = data
user = root
password = 你的数据库口令

[api]
base_url = http://127.0.0.1:0000/api/v1 
token = 你的 API Token
timeout = 30

[import]
data_dir = data/import
```

> API 模式下，Breitstein 五要点指标（活跃度 / 干净价位 / 盘整 / 情绪 / 共振，含 AVWAP、
> 投降与收复判定）全部在本地计算，API 仅替代"行情取数"环节。

### 本地 CSV 导入数据源

「本地 CSV 导入」完全离线，把按月导出的日线 K 线当作独立数据源。日线按月组织为一个文件
`daily_YYYYMM.csv`（如 `daily_202610.csv`），放在 `[import] data_dir` 指定的目录即可，
也可在「系统设置 → 上传月度 CSV」直接上传（**推荐**）。

CSV 列约定（大小写不敏感，缺省列自动补齐，多余列忽略）：

| 列         | 说明                                       | 是否必有 |
| ---------- | ---------------------------------------- | ---- |
| `trade_date` | 日期 `YYYY-MM-DD`（也兼容 `YYYY/MM/DD`）        | 是    |
| `code`      | 6 位代码或带 `SH/SZ/BJ` 前缀                  | 是    |
| `name`      | 名称（缺省填 code）                            | 否    |
| `open/high/low/close` | 价格                              | 是    |
| `volume`    | 成交量（缺省填 0）                             | 否    |
| `limit_up`  | 涨停价（缺省填 0）                             | 否    |
| `is_st`     | 是否 ST（缺省填 0）                           | 否    |

导入数据不经过共享月片缓存，新导入即生效；回测 / 基准 / 面板上层零改动。

### 关于直连 MySQL 的 SQL 文件

直连取数语句 `sql_market.py` **仅供本地使用，不纳入代码仓库**（已在 `.gitignore`
忽略）。仓库中只提供接口模板 `app/current/sql_market.example.py`。需要直连时：

```powershell
Copy-Item app/current/sql_market.example.py app/current/sql_market.py
```

再按本地行情库结构补全语句。**API 模式不需要该文件**：相关导入均为可选，
缺失时 API 模式照常启动；若误用直连，页面会给出明确的降级提示。

## 四、缓存说明

平台采用两层本地缓存，目录为 `data/cache/`。

### 面板磁盘持久化

面板缓存默认只存在于**内存**中，关闭软件即释放，下次打开需重新计算指标。
平台提供可选的**磁盘持久化**：

- **开关位置**：在「系统设置」中开启 / 关闭，对应 `config/config.ini` 的
  `[cache] panel_disk_cache`（默认 `false`，即关闭）。
- **开启后**：算好指标的面板会写入 `data/cache/`，重启软件后可直接复用，
  省去重复计算，对大股票池、长区间的二次打开提速明显，代价是占用额外磁盘空间。
- **自动失效**：持久化面板与参数、`panel_version` 绑定；修改参数或升级版本后，
  旧面板不会被误用，会自动重建。关闭开关后，已落盘的面板不再被读取，可手动删除。

## 六、常见问题

**Q：双击 start.bat 闪退或提示找不到 Python？**
A：确认 `runtime/python312/python.exe` 与 `pylibs` 目录完整存在；
错误信息会写入 `logs/run-YYYYMMDD.err.log`，可据此排查。

**Q：首次启动自动下载运行环境失败怎么办？**
A：分三步排查——

1. **临时网络问题**：脚本内置最多 3 次尝试，直接**再双击一次 `start.bat`** 重试即可，
   已下载的部分会断点续传，无需重新开始。
2. **确认网络可达 / 无代理拦截**：若反复失败，检查是否能正常访问下载地址
   （取 `app/current/manifest.json` 里 `runtime_download_url` 的网址）。
3. **手动下载兜底**（最稳妥、适用于自动下载一直失败时）：以下两步走完，再启动即可跳过下载。

   **第 1 步：下载运行时压缩包 `python312-win.zip`（约 150MB）**
   - 首选地址（gitcode，直链，浏览器直接保存即可）：
     `https://gitcode.com/rxlibpub/rxlib_lance_b/releases/download/py312-v1/python312-win.zip`
   - 备用地址（gitee，人工访问时需按页面提示完成一次机器验证）：
     `https://gitee.com/rxlibpub/rxlib_lance_b/archive/refs/tags/py312-v1.zip`
   - 下载完成后，把文件放（或移动）到项目根目录，例如 `D:\rxlib_lance_b\python312-win.zip`。

   **第 2 步：校验并解压**
   - （可选）校验文件是否完整：在项目根目录打开 PowerShell，运行：
     ```powershell
     Get-FileHash .\python312-win.zip -Algorithm SHA256
     ```
     把输出的一长串哈希，与 `app\current\manifest.json` 里的 `runtime_sha256` 对比，
     应完全一致（不一致说明文件损坏/被篡改，请重新下载）。
   - 解压：右键 `python312-win.zip` → **全部解压缩 / 解压到当前文件夹**。压缩包内部自带一
     个名为 `python312` 的顶层文件夹，解压后应产生：`python312` 文件夹 + `runtime` 文件夹并列。
   - 将 `python312` 文件夹**移动**到 `runtime` 文件夹**里面**，使最终路径为：
     `runtime\python312\python.exe`（此文件存在即表示就绪）。
   - 确认无误后再双击 `start.bat`，这次会自动跳过下载、直接启动。

   > 注：`manifest.json` 中 `runtime_sha256` 用于防止下载被篡改/损坏，自动下载时校验不过
   > 脚本会删除缓存并重新下载。手动解压请务必把 `python312` 放进 `runtime\` 内，
   > 保证 `runtime\python312\python.exe` 路径拼写正确。

**Q：页面提示"直连 MySQL 取数失败，已改用本地缓存行情"？**
A：说明当前选择了直连模式但本地缺少 `sql_market.py`（或数据库不可用），
系统已自动降级使用历史缓存，数据区间可能被截断。可改用 API 模式，
或参照第三节放置本地 `sql_market.py`。

**Q：更换电脑 / 重新克隆代码后历史数据还在吗？**
A：`runtime/`、`config/`、`data/cache/` 默认不纳入代码仓库。其中缓存与原电脑的
Windows 用户绑定，**直接拷贝过去也无法解密**，无需迁移；在新电脑上配置好数据源后，
平台会自动重新取数、重建加密缓存。运行环境则由首次启动自动下载补齐。

**Q：提示缓存解密失败 / 完整性校验失败怎么办？**
A：说明对应缓存已损坏或不属于当前 Windows 用户。删除 `data/cache/` 内相关
`.pkl` 文件后重新运行即可，平台会重新取数并重建；历史月片可随时安全删除。

**Q：如何设置开机自启？**
A：以 PowerShell 执行 `.\install-task.ps1` 注册；取消则执行 `.\uninstall-task.ps1`。
